# v0.28.0 六项更新：城池经营与共享世界

类型：Addition / Integration。工作流：CCGS minimal。状态：IMPLEMENTED / LOCAL QA；Supabase 云端启用待独立组织与费用确认。

用户授权此前建议 1–6 全部实现：多城独立经营、城际运输和调遣、名将池与图鉴、高级守城和派遣侦察、将领技能成长、跨设备存档与共享世界争夺和联盟援军。继续遵守画像抓将、骑兵速度用途、缴获/运输允许爆仓、任务据点逐步发现等既有约定。大型本地回归与长局后续集中进行，本轮执行必要的数据、结算、并发和浏览器检查。

## 可验收的结果

1. 旧存档主城及已占领城市保留；独立城市拥有资源、建筑、产业、科技、税率、城守、驻军及队列。切城不丢进度，异城正常生产和施工；固定世界地形与坐标不随切城变更。新占城/平地筑城受爵位额度限制，已超额旧城市保留。
2. 运输与调遣报价含来源、目标、负重、耗粮、用时。确认后固定来源/目标，切城不改变到货或返程城市；资源与军队只结算一次。运输货物允许爆仓，有明确在途/返程状态。
3. 至少十二条名将定义和图鉴，保留原三条属性、价格、画像及招降条件。新增地区和门槛明确，无线索重抽。多人名将使用服务端唯一归属。
4. 基础守城继续兼容；新增骑兵、弓兵与器械三种敌军阵容，难度和奖励可预览。侦察实际派遣、消耗粮食、到达获取分级情报、返城恢复幸存斥候，报告有有效期和失败结果。
5. 技能成长先实现骑兵、弓兵、器械与内政四种专长，少而明确；费用与效果预览、旧将领迁移、战斗/行军快照保证途中修改不影响既有战况。本轮不额外扩展宝石和坐骑。
6. Supabase Auth / Postgres / Edge 提供私人云档 CAS、服务端新建共享档、权威命令、名将竞争、玩家城市战争、联盟和援军。私人单机档与共享世界隔离；不接受客户端资源、时间或战果作为权威。每请求独立静态引擎工厂，服务端时间、命令白名单、交易事务、修订比较、唯一约束及幂等回执。只公开必要地图读模型；敌军详细信息由侦察授权。

面向约一百名玩家设计；实际容量结论须经集中负载测试。Free 用于开发内测，是否升级 Pro 取决于真实同时在线、消息量和结算成本。现有房地产 Supabase 项目不复用；独立游戏项目的组织和费用按创建工具要求确认后建立。

## 实现契约与职责

根代理负责多城数据、引擎投影/全城结算、物流、加载顺序、旧档保护及整合。玩法代理负责名将、技能、NPC守城和侦察规则。UI代理负责城市/物流、图鉴/技能、账号及共享世界界面。后台代理负责静态引擎构建、Supabase数据库/Edge和并发协议。核心引擎 IIFE 图谱覆盖不足，Graphify 查询后直接核对源码；更新后沿用本地代码抽取，不上传图谱。

顶层 Game.state 保持既有全局字段加当前城字段投影，realm.cities 持有每城数据；序列化前同步当前城。图谱用于影响定位，验证依靠真实接口和浏览器。服务端独立工厂按同一代码加载序列生成，避免维护第二套战斗数值。
