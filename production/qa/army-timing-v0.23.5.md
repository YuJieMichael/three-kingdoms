# 在外军队时间 v0.23.5 验证

日期：2026-10-05。用户要求能查看军队情况，包括行进时间。

## 规则与实现

军队页每支行军／返城部队显示剩余时间、已行进／全程时间、进度百分比与本地预计到达日期时刻。涵盖主次出征、占领后返城、手动出征召回与驻军召回。主将、兵种人数、目标坐标、任务类型、耗粮与操作继续显示，野地占领保留胜利后返回／驻扎计划。

ArmyOverview.timing 只读取实际 start/end，剩余与进度夹在合法范围；剩余秒向上取整，已行进秒向下取整，长时长按天／小时／分／秒拆解。formatArrival 包含日期与秒。500ms 普通刷新只改计时文字、样式与 ARIA 属性，保留卡片与操作节点；到达后由原 signature 边界渲染为等待战斗，返城完成由原 tick 结算移除。交战保留旧行军时间戳，但明确不显示路线倒计时；驻扎／采集同样不显示。没有改引擎、存档格式、路线时长或倍率规则，切换倍率不重算已发出的部队时间。

army-timing.test.cjs 新增 12 项，正常接口覆盖真实行军、两种返城、保存／离线恢复、多队切换、时钟偏差与到达等待。还覆盖无倒计时的交战／驻扎／采集、数值和日期边界、实际 HTML 生命周期，以及刷新多个计时块时保持子节点与焦点、更新进度和无障碍属性、读取不结算游戏。没有清零敌军 HP 或替换战斗结果。

## 实际浏览器观察

Run result: OBSERVED。在隔离 localhost:8138 通过设置导入明确准备存档，未导入或重置正式玩家存档。城市／科技／100,000 名弓箭兵属于准备 checkpoint；所有派兵、胜利、驻军和起止时刻由正常 Game API 生成。夹具模拟从生成前 3 分钟开始，准备战斗在过去完成，最后派遣／召回对齐真实生成时刻；未改敌军、结算结果或活动路线时间戳。野地行军实际封顶 90 秒、驻军召回最长 45 秒，夹具未人为延长。

多队准备存档有 84 秒勾选返回占领、74 秒默认驻扎占领、45 秒驻军返城，以及一支驻扎森林的 300 人部队。实际观察两条出征倒计时分别从 42→24 秒、32→14 秒，进度 50→72%、57→82%，ETA 各自不变。刷新后起止时间相同，继续 23／13 秒；45 秒驻军返城实际完成，城内从 19,700 增至 49,700，总现役仍 100,000。两支行军结束后自动显示已抵达、原全程时长和进入战斗按钮。观察数据保存在工作区 browser-time-observation.json。

另一个正常 90 秒远程掠夺检查点显示全程 1 分 30 秒、已行进 1 分 20 秒、剩余 10 秒、89% 进度。手机下一次观察剩余 9 秒、90%。已抵达的近森林占领点击进入战斗、暂停自动计时，军队卡显示交战中与 0 个路线计时块；手动正常三回合胜利后点击军队，实际显示 300 人返城、全程 5 秒、剩余 5 秒。

正常胜利的远野地驻军在浏览器点击召回，实际显示 30,000 人返城、全程 45 秒。手机观察剩余 25 秒、已行进 20 秒、45%，刷新后已行进 21 秒、47%，原预计返城时刻不变。后续检查已全部归城：驻城 100,000 人、现役 100,000 人、暂无出征或驻军部队，返城行不会残留。
