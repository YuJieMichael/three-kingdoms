## 优先发现与更新建议

### P1 · 确认缺陷：旧标签页能够覆盖新进度

两个独立运行环境共享同一存储，用原生产代码正常操作：A领取首阶礼包，黄金15000、领取标记和道具正常；B从旧状态调税保存；再次加载后黄金回5000，领取标记和道具消失，存档仍通过校验。

根因是 [engine.js:143](/Users/lihuazeng/Documents/Codex/2026-10-05/e/work/three-kingdoms/engine.js:143) 全量写入没有版本/写者冲突检查，[定时保存](/Users/lihuazeng/Documents/Codex/2026-10-05/e/work/three-kingdoms/app.js:53) 与 [隐藏/退出保存](/Users/lihuazeng/Documents/Codex/2026-10-05/e/work/three-kingdoms/app.js:54) 均可能写旧状态。这是可复现的正常多标签缺陷；本次证据是共享存储的两个VM，尚未实测真实浏览器双标签发生率。

建议先实现单个活跃写入页面、明确接管、版本冲突提示及最近有效备份，随后接跨设备云存档。另两个故障注入探针发现坏档或一次读取异常后，[init](/Users/lihuazeng/Documents/Codex/2026-10-05/e/work/three-kingdoms/engine.js:194) 会新建城池并覆盖唯一原始数据，属于P2恢复缺口；没有证据说明游戏会自行产生坏档。

验收：旧页面不能静默覆盖新进度；重载、退出保存和接管一致；异常读取或无效存档保留原始数据并提供恢复入口。详见 [独立QA报告](/Users/lihuazeng/Documents/Codex/2026-10-05/e/outputs/game-evaluation-v0.23.5/quality/quality-findings.md)。

### P2 · 平衡风险：黄金主要来自任务，资源田被奖励库存遮蔽

正常首弓路线任务给金 **771000**，前两阶礼包 **30000**，税收 **8.60**，实际支出 **51460**，余额 **754548.60**。任务占新收入96.25%（不含初始5000）；十阶余额约225.37–230.46万。该首弓路线四资源自然净增均为0，因为合法奖励库存一直高于容量。

任务与礼包支持快速起步，但奖励显著超过这条路线的消费。建议把 [建筑任务](/Users/lihuazeng/Documents/Codex/2026-10-05/e/work/three-kingdoms/reward-data.js:46)、[科技任务](/Users/lihuazeng/Documents/Codex/2026-10-05/e/work/three-kingdoms/reward-data.js:57)、礼包、补兵、科技和装备消费放在一起调，保持用户要求的爆仓规则。缺少全局盈余目标，当前不指定削减百分比，也不把这一条路线推断成全部后期通胀。

验收：明确首弓与各官府阶段预期库存/缺口，再运行合法路线和并行征战路线；现有小于90分钟、固定十阶24–48小时目标同时复核。详见 [经济成长报告](/Users/lihuazeng/Documents/Codex/2026-10-05/e/outputs/game-evaluation-v0.23.5/economy/economy-findings.md)。

### P2 · 设计接续：城守培养和十级后战役目标

建筑经验已有效：首弓城建获得520经验，苏砚Lv.4有9点未分配；十阶1420经验，Lv.6有15点。将领界面已有培养说明，但主成长路线没有带玩家使用这些点。合法投内政的单种子对照十阶23.33小时，未加点42.99小时；差异包含原工期和固定规格加速的共同作用，不能称15点直接缩短46%工期。

建议第一次城守升级时提示培养入口与工期收益，长工程期间提供明确征战或扩兵目标。官府十级结束时本固定路线仍只有30弓、1次胜利、官职1，主引导仅剩泛泛继续征战；应继续解析史诗、章节和军备缺口。[城守经验](/Users/lihuazeng/Documents/Codex/2026-10-05/e/work/three-kingdoms/hero-system.js:36)、[分配属性](/Users/lihuazeng/Documents/Codex/2026-10-05/e/work/three-kingdoms/hero-system.js:49)、[引导终点](/Users/lihuazeng/Documents/Codex/2026-10-05/e/work/three-kingdoms/growth-guide.js:68)。

验收：玩家能从升级提示打开培养并看懂作用；十级后可直接看到下一战役目标、配兵需求和入口。后续正常经济模拟覆盖章节，而非预设高级兵力。

### P2 · 后期目标：护械实际参战及轮换挑战

两种种子中，1100弓＋5冲车坚守，冲车全程停在位置0、未攻城仍全部存活，25回合胜并获得首次额外40军功。当前 [挑战规则](/Users/lihuazeng/Documents/Codex/2026-10-05/e/work/three-kingdoms/war-orders.js:38) 只要求器械数量与存活率，结算符合公开字面条件；这是教学目标的设计缺口，不能称错误发奖。

建议增加器械至少实际攻击城防一次的要求，并保留80%战场存活；先验证弓主力配少量器械可通过指挥达标。盾兵已有可见保护收益，枪骑应各有一场能证明其用途的同预算对照，随后加入少量轮换敌将或可选分支。

第三章已经通过门墙、敌将和器械改变玩法；当前三条军令各十阶、三个一次性额外奖励挑战，全部完成后主要固定复刷和兑换。新增变化应先改变配兵/指令/风险收益选择，再扩展同类阶数。详见 [战斗后期报告](/Users/lihuazeng/Documents/Codex/2026-10-05/e/outputs/game-evaluation-v0.23.5/combat/combat-findings.md)。

### P2 · 手机打磨：内容空间、小字和加速层级

360×800实测文档无横向溢出，主内容区只有478像素高，固定顶部/底部占40.25%高度；展开成长卡时城市首屏约一行完整格子。资源产量与容量为8像素，黄金和滑动提示在横滑区最后一项。导航44像素高、地图格47.33像素，基本点击范围已具备。

从成长卡到完成一次加速仍需四次点击，六个规格同时出现，零库存可进入随后禁用的确认页。建议手机成长卡压缩为可展开的短目标，常驻资源滑动提示，放大关键小字，加速优先展示已有且最少浪费的规格。首战配兵可优先显示实际驻城兵种，保留完整列表入口与所有核对信息。[资源提示](/Users/lihuazeng/Documents/Codex/2026-10-05/e/work/three-kingdoms/war-theme.css:39)、[加速列表](/Users/lihuazeng/Documents/Codex/2026-10-05/e/work/three-kingdoms/speedup-ui.js:7)。保持现有写实古代战争方向，先改善信息排版。

验收：360/390布局可完成成长、加速、地图、配兵与战斗；再通过真实iPhone/Android检查触控、键盘、后台和浏览器高度。当前窄视口证据见 [试玩记录](/Users/lihuazeng/Documents/Codex/2026-10-05/e/outputs/game-evaluation-v0.23.5/ui/raw-notes.md)。

## 建议更新顺序

1. **保护存档，同时优化手机高频操作。** 多标签写入、备份恢复、短成长卡、资源发现与加速选择。
2. **连接成长并整体调经济。** 城守培养、长工程并行目标、十级后具体战役引导；设清楚目标再调任务与礼包。
3. **补有效后期变化。** 护械实际参与、枪骑用途对照、轮换/分支战术目标，保持弓兵主力。
4. **接手机电脑同账号进度。** 登录、云存档、版本冲突与设备接管一起验收；若目标是多人同服，资源、行军、战斗、归属和随机奖励必须迁到权威服务器，不能用云快照同步替代。

以上是评估建议，未在本轮修改规则或接入云服务。
