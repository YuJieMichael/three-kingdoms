# CCGS QA-lead：v0.28.0 游戏质量测评

日期：2026-10-05。范围：当前工作区 v0.28.0 候选版；桌面浏览器和手机宽度预览、单机经营及本地共享服务。依据：[本版验收](../realm-online-v0.28.0.md)、[六项规格](../../../design/quick-specs/realm-online-v0.28.0.md)、[后台运行指南](../../../online/README.md)和已留存证据。本报告没有新跑全量回归或长局。

**结论：适合继续受控试玩。经营和战斗的关联比此前完整，后期已经有新的决策；完整公网多人发布仍未就绪。** 自动测试能证明规则和存档在已覆盖场景下正确，不能证明等待舒服、资源平衡或玩家愿意长期回来。

## 方法与证据

采用 Codex 适配的 CCGS `qa-lead` 角色和 `playtest-report` 分析方法，参考 `release-checklist` 判断发布范围。不是调用一个远程 Claude 评测服务。配置解析为 `rigor/workflow/qa.level=minimal`、`review_mode=solo`，没有另行创意总监审批；商店认证档位未配置，本次浏览器原型评估不延伸为 Steam、主机或手机商店认证。

后台实现和本次 QA-lead 证据整理由同一代理完成；原样 SQL 由独立检查代理验证，浏览器 SDK 流程由根代理实际操作。此报告不替代独立安全审计或真人盲测。

“100并发”指**同一 actor、同一 revision、100个不同操作 ID**在内存适配器竞争，严格得到1成功／99个冲突；同 ID 20次并发重试只提交一次。它证明该适配路径的竞争断言，不是100名真实玩家通过网络同时在线。10组 SQL 每组包含多项断言，不能与前两列直接合称“132个完整游戏测试”。

兼容补验先审了5个包含 `engine.js` 的自定义加载器：4个固定列表已有完整的城市、技能数据、技能系统、侦察系统加载顺序；另一个从入口自动读取顺序，没有漏模块。更新[首战测试](../../../tests/first-battle-guide.test.cjs)与[成长模拟器](../../../tests/balance/archer-onboarding.cjs)以推进真实侦察时钟，取得报告后出征不强制等斥候返城。两项[旧礼包测试](../../../tests/onboarding.test.cjs)曾把新多城档的顶层资源改成旧值，却保留不同的城池镜像；删除夹具中旧版不存在的 `realm` 后迁移和金保留检查通过。这是测试夹具兼容修正，没有放宽实际存档校验或改动游戏核心。后台21项与SQL10组未重复执行。

## 当前体验判断

| 维度 | 观察与设计推断 | 置信度 |
| --- | --- | --- |
| 新手方向 | 主线、十阶礼包和弓兵目标给了具体下一步。共享新城确实从官府1级开始，礼包和建设走服务器规则。首次弓兵路线在本版未自然重测。 | 中 |
| 成长选择 | 城池独立资源、兵城／资源城／投石城、运输、将领专长，能让玩家选择怎么经营和配兵。 | 中高：功能成立；策略是否均衡待观察 |
| 战斗理解 | 行军状态、正常战斗逐回合信息及共享损失／缴获报告，使结果更可追溯。侦察的数量未知与有效期也有实测。 | 中高：信息存在；玩家能否据此改配兵未盲测 |
| 后期吸引力 | 抓将、扩城、运输和高级守城把原本单纯等待变为一组有用途的目标。是否会形成日复一日的有趣循环，尚无长局数据。 | 中低 |
| 操作负担 | 自动研究／建设、城外样板及批量领取减少重复操作；城多以后，切城、运输与援军管理也可能增加负担。手机背包与商城紧凑布局改善可见性。 | 中 |
| 多人完整度 | 权威命令、唯一归属、掠夺、联盟和援军已有实际本地流程。共享 PvP 是自动掠夺原型，尚无城池易主、完整战术指挥与玩家反侦察。 | 高：实现边界明确 |

这版最有价值的改进是系统开始互相需要：兵城要粮，资源城支援建设，运输把两者连接；画像、爵位、黄金／珍宝和招贤馆容量共同约束抓将；技能为将领培养提供方向。它们有机会改善后期乏味，但“系统更多”本身并不等于“更好玩”。

仍需留意三个体验问题：第一次体验是否真的把玩家带到弓兵、普通玩家能否在付出损失后补回部队、多城收益是否足以抵消管理负担。现有人工兵力和资源夹具无法回答它们。

历史弓兵模拟曾得到“使用合法道具约49.81分钟，不用道具约13.70小时”，见[历史成长记录](../../../design/balance/archer-onboarding-2026-10-05.md)。这些是旧版可控时钟路线，v0.28.0没有重跑自然成长。它提醒加速道具的引导非常重要，不能把49.81分钟写成当前真人保证。十阶或两章历史模拟也不等同本版多城长局。

## 发布范围与风险

| 优先级 | 分类 | 已知范围 | 对发布的影响 |
| --- | --- | --- | --- |
| P1 | 远端功能未启用 | 独立 Supabase 项目、迁移／Edge 回执、Auth 邮件、Cron／Vault尚未完成公网验收 | 不应宣称“手机和电脑已可公网同进度一起玩”或“正式多人上线” |
| P1 | 容量未评估 | 没有100名不同玩家、真实网络、多数据库连接、持续延迟／失败率／成本数据 | 不能承诺百人同时在线容量或据此选择付费档位 |
| P2 | 玩法规则差异 | 单机战斗可逐回合指挥；共享战斗自动结算，使用原兵种／科技／将领及冻结技能，但动作顺序、工事处理与回合过程更简化 | 需明确“共享自动掠夺原型”，不能暗示两模式战术完全等价 |
| P2 | 结算体验 | 本地工作器每15秒检查；远端工作器需部署并配置周期任务。显式共享结算仍可触发，普通操作遇已抵达部队会要求先结算 | 避免再次出现战后频繁确认的摩擦；需集中观察正常玩家操作次数 |
| P2 | 成长与经济 | 未完成本版从零到弓兵、两章、扩城、高级守城及数日养兵的自然长局 | 不能以夹具通关推出“礼包／补兵／军功收益平衡” |
| P2 | 跨设备体验 | 手机宽度模拟已检查，实体手机、软键盘、安全区域、后台挂起与真正跨设备冲突恢复未验 | 浏览器响应式支持不等于手机端全面验收 |
| P3 | UI证据覆盖 | 背包／商城／共享建设有截图；多城、运输、侦察等还有文字操作证据，未独立留存每个新弹窗的最终截图 | 全面 UI／Visual 签字仍为 NOT ASSESSED，不据此声称所有屏幕已验收 |

这些是已知发布范围和验证缺口，不冒充已复现的游戏 Bug。开发中发现的 CORS版本头、共享将领复用、工事技能作用范围、名将竞争绕过及新城重址已修复并有针对性检查。未读取到独立开放 Bug 台账，不能报告“全游戏0个S1／S2”；已覆盖路径内未保留未解决的复现阻断。

本地候选版可进入下一轮受控试玩；完整公网多人发布判断为 **NOT READY**，因为远端功能尚未启用。全量回归、长局、实体设备与真实网络容量分别为 **NOT ASSESSED**。本报告不是正式发布批准，也不是 Pages 或 Supabase 部署回执。

补充：这里的NOT ASSESSED指本地集中回归、自然长局、实体设备与真实网络容量。发布阶段既有远程CI实际跑323项，首轮14个旧测试兼容失败随后复现并按真实规则修正，另27项必要检查通过；没有改变源规则或放宽存档验证。精确提交的最终远程CI与Pages结果以发布回执为准，不将前述边界解释为GitHub从未运行检查。详见[发布兼容补验](../realm-online-v0.28.0.md#发布ci兼容补验)。

## 建议下一轮只集中验证三件事

1. **第一次成长是否顺畅。** 从真实新档到30弓兵、首次侦察和首战，记录实际耗时、卡资源次数、加速道具是否被理解、玩家是否能说出当前目标。按用户约定留待集中测试，不在本次补跑。
2. **扩城有没有持续意义。** 连续经营兵城与资源城，观察运输频率、补兵成本、粮食断供、多城管理点击次数；每次守城和掠夺同时记录损失价值、缴获价值与实际入库。先看数据再调奖励。
3. **共享世界是否可靠而省操作。** 先完成独立云项目部署及账号／定时结算验收，再逐级真实玩家压测。测跨设备旧修订、重试、断网、名将同时抵达、联盟援军伤亡／召回；同时记录玩家被迫点“结算”的次数。

优先顺序建议是先完成可测的真实连接与观察，再依据长局结果调资源和难度。当前不需要继续堆更多系统来代替验证。
