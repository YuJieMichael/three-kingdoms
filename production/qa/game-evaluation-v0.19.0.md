# 三国城志 v0.19.0 游戏评估

评估日期：2026-10-05。对象：本轮本地候选版。方法：源码与规则检查、74 项自动测试、正常经济 API 模拟、桌面和 360/390 像素浏览器 UI 检查。评分为开发评审的主观判断，不是用户调研结果；没有留存、付费、市场竞品或真实玩家样本。

## 结论

作为个人单机 PVE 原型，约 7/10：城建—资源—科技—练兵—征服—奖励循环成立，已适合邀请少量玩家试玩。作为长期正式版本仍需打磨节奏、引导与战斗差异；现有测试不能证明玩家会长期留下。当前应先改善前 30 分钟，再决定是否扩充第四章。

| 维度 | 主观评分 | 依据与主要问题 |
|---|---:|---|
| 核心循环 | 8/10 | 建造和人口支持军队，科技与章节产量奖励回流发展；补兵有真实成本。需要更清晰显示当前瓶颈和下一目标。 |
| 战斗策略 | 7/10 | 兵种克制、命令、敌将、门墙、箭楼与器械生效。正常路线采用弓兵占多数的固定组合，尚不能证明多种阵容同样可行；应测试骑兵、器械与防守型替代解法。 |
| 章节与成长节奏 | 6/10 | 第二章六关、第三章五关可通，但普通钟约五天的模拟路径偏长。等待是否有趣尚未经过玩家验证。 |
| 挂机便利 | 8/10 | 自动研究和建设受资源额度约束，记录可持久保存。关闭浏览器后资源仅结算最多八小时，已有队列会完成，战斗及自动指挥仍需开页；需明确这些边界。 |
| 界面与美术 | 7/10 | 古代战争配色、城坊和地图风格统一，手机按钮与布局改善。信息密度仍高；长弹窗、资源横向滑动和深层入口增加学习成本。 |
| 技术可靠性 | 8/10 | 74 项回归覆盖付款、迁移、一次领奖、门墙、额度和离线记录。浏览器本地存档限制跨设备延续；暂无完整第一章至第三章浏览器长局证据。 |
| 长期可玩性 | 5/10 | 章节提供目标，但资源和军队成长仍是主要循环；完成后缺少经过验证的挑战变化和复玩目标。 |

## 已验证的证据

正常模拟不直接赠送军队、不直接设置资源或建筑等级，以真实建造、研究、分批训练、行军和任务奖励推进；只预设第一章县城归属检查点。第二章 1400 人准备路线六关 3–8 回合；第三章正常补兵到 2100 人并领取合法剧情器械，五关 4–13 回合。两种随机种子通过，未补兵方案在第三章第三关失败。不能据此认定难度对所有玩家都合适，也未模拟额外守城损耗。

60 倍路线约 2.42–3.42 小时，普通钟约 129.15 小时。任务补给包含在正常来源中；这是模拟等待时间，不是人类完整实玩或纯资源田收入时间。倍率不统一加速收入，比较时须说明。

桌面助手保存设置成功；粮食输入在定时刷新期间保持值与焦点。390 像素助手表单宽度/滚动宽度均 336，checkbox 22 像素；360/390 城市地图检查见手机 QA。实体 iOS/Android、软键盘、触屏拖动未测试。

## 改进优先级

1. **先做新手目标与瓶颈提示。** 每次显示一个主目标、缺少什么、从哪里获得，并直接跳转操作。首局避免一次展示全部系统；试玩时记录五名新玩家前 30 分钟的困惑与卡点。
2. **统一并解释时间。** 清楚区分正常模式与试玩倍率，队列显示预计完成时间，资源不足显示预计积累时间。先收集前 30 分钟、首战与首章所需时间，再决定缩短哪些等待，避免凭一条路线全局降价。
3. **让战斗结果可解释。** 战报显示伤亡主要原因、兵种克制、门墙贡献及补兵建议。对同一关测试至少三种合理阵容，确认替代策略而非单一堆弓解法。
4. **明确珠宝来源。** 晋升面板显示各珠宝已知来源与可达章节；保留珠宝门槛，但减少“声望够了却不知道如何晋升”的困惑。先核算固定与随机收入，再改掉率。
5. **验证真实长局和手机。** 完整第一章到第三章，不预设征服；分别观察离线、来袭、资源缺口和存档恢复。实体手机验证弹窗、键盘及地图点击。
6. **最后扩展长期目标。** 在上述证据成立后试做可选挑战、不同敌军组合与章节复战。先小范围验证，避免仅增加更大数值和更多关卡。

## 下一次试玩验收

建议邀请五名没有看过代码的玩家，记录：首次成功建造/练兵/出征的时间、前三个卡点、首次伤亡后是否知道如何恢复、能否找到珠宝与科技来源、是否理解挂机边界、30 分钟后是否愿意继续。这里只提出评估方法，没有伪造实际结果。
