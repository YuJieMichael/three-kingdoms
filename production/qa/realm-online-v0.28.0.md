# v0.28.0 六项更新验收

状态：实现完成并通过必要本地定向检查。玩法／存档103项、后台21项通过；原样SQL另有10组实际PostgreSQL校验。重复执行同一文件不重复计数。本轮没有运行本地全量回归、自然成长长局或线上容量测试。本记录不作为Pages发布或Supabase部署回执。

规格见 [六项更新](../../design/quick-specs/realm-online-v0.28.0.md)，规则见 [RULES](../../RULES.md)，构建和远程部署步骤见 [后台指南](../../online/README.md)。账号／私人云档／共享世界代码已实现，独立Supabase组织／项目与费用选择尚未确认，远程后台尚未启用；未复用其他业务项目。

## 六项实现与观察范围

1. **多城独立经营**：主城与旧已占城市迁移为独立城市数据，资源、建筑、产业、科技、驻军、城守、税率和队列分开；切城保留异城时间推进。真实攻占黄巾／普通城市后有独立scope，未勾返回驻入新城、勾选返回回原城；爵位额度满时占领拒绝且不扣出征费用，掠夺仍可进行。两城建筑经验分别发给各自城守。最高官府解锁的全局礼包在1级新城也能校验和重载，不能重复领。
2. **运输与调遣**：报价与确认使用真实来源、目的地、负重、粮耗和时间，资源／兵力出发扣除；运抵爆仓、运输队返城、调遣归目的城与召回都有定向检查。切城、离线及重载不能改目的地或重复入库／归兵。
3. **野将池与图鉴**：十二条定义、九位新增地区名将的客栈和爵位门槛、稳定线索、画像前置、招贤馆容量与原三条兼容。共享世界另验证先抵达且获胜者获得唯一历史名将、后来队伍返回且不复制俘将。
4. **高级守城与实际侦察**：三种高级阵容的门槛、难度、付费、奖励、失败无奖、旧周期兼容、烽火台精度和开战将领快照。斥候出发扣粮、固定坐标和敌军快照、分级成功／失败、损失与返城、人口／养兵占用、情报有效期、旧档迁移和只读保护。
5. **将领专长**：四条互斥路线、五级、等级与军功／黄金／珍宝费用、军功账本、空闲将领条件、技能快照、内政加成。骑军包含轻骑／铁骑／斥候攻击和纯骑编队速度，混入弓兵不加速；旧装备、自由点与无技能将领保留。
6. **私人云档与共享世界**：静态原引擎工厂隔离时间、随机数和存储；服务端创建共享档、普通命令白名单、来源城、修订CAS、幂等回放、禁止客户端快照注入。私人云档独立，名将／城池竞争、基础PVP掠夺与工事、联盟元数据CAS、援军归属／耗粮／召回、相关战报读模型，以及真实本地注册／登录／刷新／退出与SQLite重启持久化。原地图捕获在已抵达共享竞争者未结算时被拒绝，先结算后保持唯一归属；新筑城池有全世界唯一占址，加入玩家城址避让已筑城市，不能从普通NPC攻打绕过玩家归属；攻城专长的工事伤害倍率只作用于冲车／投石。

共享PVP为自动掠夺结算原型，尚未实现玩家城池易主、24小时占领、完整战术指挥或玩家城市反侦察。不要把第六项表述为原版完整多人系统。

## 原样迁移：实际SQL／RLS／RPC

命令：`npm run online:sql-check`（等价 `node scripts/verify-online-sql.mjs`）。开发依赖由pnpm锁定为`@electric-sql/pglite@0.5.8`，运行于PostgreSQL18.3 WASM。脚本原样加载 [正式迁移](../../supabase/migrations/20261005213008_realm_online_v028.sql)，不重写SQL；只模拟Supabase必要的auth.users、auth.sessions、auth.uid和anon／authenticated／service_role前置。

最终验证迁移SHA256：`a6fa39ed6324f384063e0ba9e7901f8181d18f068685683dda8db042eb4d47e6`。冻结服务端工厂为23份源码，源SHA256：`389365bf7dbd9936716634a3f2aceb4bb448d6f5cb6a95a6299793f01f3f11e7`。

| 组 | 实际执行的断言 | 结果 |
| --- | --- | --- |
| 1 | 原样迁移创建9张启用RLS的表、2项own-read policy及可执行SQL／PLpgSQL函数 | 通过 |
| 2 | 服务角色创建3位玩家的不同城址，同一加入请求回放一次 | 通过 |
| 3 | authenticated只读自己共享档／私人档；他人私人档不可读，anon读取、直接写入及客户端RPC被拒绝 | 通过 |

## 独立浏览器预览

独立预览 `http://127.0.0.1:8138/`，1280×900与390×844下，通过设置导入人工准备的两城检查点：分城独立资源30,000、官府1级、无城守；切回主城后保留原主城资源和队列。该检查点不是用户自然成长存档。

从主城正常预览并确认木材20,000、辎重10辆运输：报价去程44秒、粮耗30，来源木材变470,000、驻城辎重变20。抵达后分城木材50,000，超过容量10,000仍足额入库；运输队返城后主城辎重恢复30，重载没有重复入库／归兵。图鉴显示12位将领，技能面板展示4条路线、真实费用和军功不足的禁用原因。

正常派出10名斥候，去程2秒、返程2秒，报告仅知兵种、数量未知、有效期15分钟；损失1名，原50名斥候返城后变49名。守城检查点仍在新手保护，未触发正式波次；浏览器仅核对守将／配兵界面及烽火台提示，高级阵容、付费和战斗结果依上方定向检查，不记作浏览器正式守城通过。
